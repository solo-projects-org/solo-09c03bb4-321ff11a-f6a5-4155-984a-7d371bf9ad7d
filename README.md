# 空气站站月文件服务

空气站数据员收到**更正日档**后，用本服务重做供数仓取数的**站月文件**。

- **FastAPI** 提供单实例网页服务（上传、状态、重试、下载）
- **DuckDB** 把单站单 UTC 日 CSV 转写为日 Parquet，并把同站同月的日档合并为月 Parquet
- **SQLite（WAL）** 保存日档/月档依赖关系与作业进度
- 全部 CSV、Parquet、数据库都写入挂载的数据卷 `/data`，容器重启不丢状态

## 数据契约

上传文件为**单站、单 UTC 日**的 CSV，表头固定：

```
station,utc_seconds,pm25
ST001,1794268800,12
```

- `station`：站号（字母数字及 `._-`，1–32 字符）
- `utc_seconds`：非负整数 UTC 秒，所有行必须落在同一个 UTC 自然日
- `pm25`：非负整数，单位 μg/m³
- 同一时间戳不得重复；一份文件只能有一个站号
- 同站同日重复上传 = **整份替换**。版本先后**只以“CSV 已保存并登记成功”的顺序为准**
  （`daily_versions.csv_saved=1` 的自增 id）；校验失败或保存失败的上传会被整体丢弃，
  不占用有效版本、不改变任何既有状态

## 版本判断与更正规则（核心正确性）

同站同日哪个版本是“最新”，只看**已成功保存并登记**的上传先后（id 最大者），与作业何时
完成无关。由此得到以下硬性保证：

1. **旧作业永不回滚**：新更正接收成功后，旧版本作业无论迟到完成、被手动重试、还是重启后
   恢复，都不能重新成为当前日档，也不会再触发/发布月文件——它在出队时即被判为 `obsolete`。
2. **日档切换在发布事务内二次复核**：转写完成、准备置 `is_current` 时会在写锁内再次确认本
   版本仍是最新已接收版本，否则只留存文件、标记作废，绝不顶掉新日档。
3. **补算未完成不冒充最新**：最新更正还在转写（待补算）或转写失败时，旧的完整日档/月文件
   仍可下载，但页面与 `/api/status` 显示“待补算/失败”，不会标“最新”。
4. **月文件覆盖全部最新日档才可标最新**：月作业在合并前与发布事务内都校验同站当月**每个**
   最新已接收日档都已 `ready + is_current`；只要有一个未补算完就保持排队（补算中），有失败
   则作业失败并提示先重试日档，绝不把旧内容报成最新。
5. **校验/保存失败零影响**：校验先于一切写盘；CSV 落盘失败会删除预登记行，原日档、原月文件
   原样保留。
6. **重启自动续算**：启动恢复把中断的 running 作业重置为 pending；已保存且仍是最新版本的
   中断任务自动续算（无需手动重试），已被新更正取代的旧任务直接作废。

## 快速启动

```bash
docker compose up --build
# 打开 http://localhost:8000
```

带故障注入的**演示**模式（用于网页/脚本演示“转写失败 → 重试”，默认关闭）：

```bash
docker compose --profile demo -f docker-compose.yml -f docker-compose.demo.yml up --build
# 或本地：DEMO_FAULT=1 DATA_VOLUME=./data python3 -m uvicorn app.main:app --port 8000
```

数据全部位于命名卷 `station-data`（挂载到容器内 `/data`）：

```
/data
├── state.db            # SQLite：依赖与进度（WAL）
├── inbox/              # 校验通过的原始 CSV（按版本留存）
├── daily/<站号>/daily-<日>-v<版本>.parquet
├── monthly/<站号>/monthly-<月>-gen<代次>.parquet
└── tmp/                # 暂存区，任何下载入口都不会指向这里
```

本地无 Docker 时的运行方式：

```bash
python3 -m pip install -r requirements.txt
DATA_VOLUME=./data python3 -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

## 处理流水线

```
上传 CSV
  └─ 校验（失败：不写任何内容，原日档不动）
  └─ 原始 CSV 原子落盘 inbox/（落盘失败：删除预登记行，原状态完全不变）
  └─ 置 csv_saved=1（此刻起本上传成为同站同日“最新已接收版本”）+ 登记日作业
        └─ 工作线程：版本闸门 → DuckDB 写日 Parquet 到 tmp/ → fsync → 原子改名
              └─ 发布事务内二次复核仍是最新版本：
                    置 current、旧日档置 is_current=0、旧月档置 superseded、入队月作业
                    （若已被更新版本取代：标记 obsolete，不切换 current，不入队月作业）
                    └─ 月作业：校验同站当月【每个最新已接收日档】都 ready+current
                          ├─ 有补算中 → 作业留队（补算中），不发布
                          ├─ 有失败   → 作业失败，提示先重试日档
                          └─ 全部就绪 → 合并，发布事务内再次核对签名，过期即作废
```

### 关键正确性保证

| 需求 | 实现方式 |
| --- | --- |
| 版本先后以 CSV 保存并登记成功为准 | 仅 `csv_saved=1` 的行参与“最新”判断（取最大 id）；保存失败删除预登记行，不占版本 |
| 旧作业迟到/重试/重启都不得回滚 | 日作业出队与发布事务内两道版本闸门，非最新版本一律 `obsolete`，不切 `is_current`、不入队月作业；重试接口对非最新版本直接拒绝并作废 |
| 保存失败保留原日档 | 校验先于任何写盘；新版本在独立事务里才切换 `is_current`，旧文件从不原地覆盖 |
| 补算未完成/失败时旧文件可下载但不标最新 | 读模型按“最新已接收日档集合”派生状态：`待补算/失败`，并保留旧完整文件的下载入口 |
| 月文件覆盖全部最新日档才可标最新 | 月作业合并前 + 发布事务内双重校验每个最新日档 `ready+is_current`，签名含各日 `版本号+行数` |
| 先日后月、只重做变更日及受影响月 | 日作业优先调度；月合并只取当月 current 日档，未变更的日 Parquet 直接复用 |
| 过期月作业不能发布，须接着补算 | 同站月仅最新月作业可发布，旧作业出队即 `obsolete`；发布事务内签名重检不一致即作废并删除产物 |
| 日档一变旧月档标过期但仍可下载 | 旧 generation 置 `superseded`，文件不删除；`/download/generation/{id}` 仍可取 |
| 写盘/登记失败或中途退出，上次完整文件不丢 | 新文件一律 tmp + fsync + `os.replace`；旧月档只在发布新文件的同一事务里才改状态 |
| 重启后可下载并自动续算 | running→pending；最新版本的中断/失败日作业自动回队续算，被取代者作废；清理 tmp 与孤儿文件；队列全部持久化在 SQLite |
| 下载入口不指向半份/不存在文件 | 下载路径只来自登记行，响应前再查 `is_file()` 并限定在数据卷内，不满足就 303 回页面报错 |
| 页面显示是否最新、失败原因、可重试 | 仪表盘展示徽章（最新/待补算/失败/已过期/已被取代）、错误文本与旧完整文件下载，失败作业有“重试”按钮；10 秒自动刷新，另提供 `/api/status` JSON |

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 仪表盘页面 |
| GET | `/health` | 健康检查 |
| GET | `/api/status` | 全部日档/月档/作业状态 JSON（含派生的最新/待补算/失败状态） |
| POST | `/upload` | multipart 表单字段 `file`，上传 CSV |
| POST | `/jobs/{id}/retry` | 重试失败作业；非最新版本的旧作业会被拒绝并作废 |
| GET | `/download/monthly/{station}/{month}` | 下载当前最新月 Parquet（仅在确实为最新时提供） |
| GET | `/download/generation/{gen_id}` | 下载指定历史月文件（含已过期/补算期间的旧完整版本） |
| GET | `/download/daily/{station}/{day}` | 下载当前最新日 Parquet |
| GET | `/download/daily/version/{version_id}` | 下载指定版本日 Parquet（含补算期间可下载的旧完整版本） |
| POST | `/demo/arm-fault` | **仅演示**：`DEMO_FAULT=1` 时令下一次日转写失败一次；未开启时返回 404 |

## 样例文件与网页演示

`samples/` 附带同一站日（ST001，2026-11-10）的一系列 CSV：

- `samples/before/ST001-2026-11-10.csv`：24 条小时值（原始上传）
- `samples/after/ST001-2026-11-10.csv`：第一次更正，改 4 个读数并补 2 条半小时值（26 行）
- `samples/recheck/ST001-2026-11-10.csv`：第二次更正（校准后再修正晚高峰），用于演示连续更正
- `samples/invalid/ST001-bad.csv`：非法样例（重复时间戳 + 非整数），演示校验失败零影响

重新生成样例：`python3 scripts/gen_samples.py`

### 在网页上演示连续更正与重试

1. `docker compose up --build` 后打开 http://localhost:8000；
2. 依次上传 `before` → `after` → `recheck`（可连续上传，不必等完）：页面始终只把最新已接收
   且补算完成的版本标为“最新”，旧版本留在历史里仍可下载；
3. 上传 `invalid`：页面提示校验失败，日档/月文件状态纹丝不动；
4. 用 `--profile demo`（或 `DEMO_FAULT=1`）启动后，先调用 `POST /demo/arm-fault` 再上传一份
   更正：该版本显示“失败”、旧完整文件仍可下载但不标最新；点击该失败作业的“重试”，补算完成
   后恢复为最新，全程不会回退到旧值。

也可以用脚本一键走完上述流程（仅通过 HTTP 接口，不直接碰数据卷）：

```bash
python3 scripts/demo.py                      # 默认 http://localhost:8000
BASE_URL=http://localhost:8000 python3 scripts/demo.py
```

## 部署约束

必须**单实例**运行：工作线程与 SQLite WAL 都假定只有一个写者。
水平扩展需要把队列换成外部 Broker，不在本版本范围内。
